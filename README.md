# SearchEngine

Консольный поисковый движок на C++17, разработанный в рамках итогового проекта курса Skillbox «Разработчик на C++ с нуля».

Программа выполняет поиск по набору текстовых документов. Список файлов и параметры поиска задаются в `config.json`, запросы — в `requests.json`. Результаты сохраняются в `answers.json`.

## Возможности

- Загрузка и индексация `.txt`-документов из конфигурации.
- Построение инвертированного индекса с подсчётом частоты слов в каждом документе.
- Параллельная обработка документов с помощью `std::thread`.
- Поиск по нескольким словам и ранжирование найденных документов.
- Сортировка результатов по релевантности и ограничение количества ответов.
- Проверка входных JSON-файлов и обработка ошибок чтения документов.

## Требования

- Компилятор с поддержкой C++17.
- CMake 3.20 или новее.
- Библиотеки [nlohmann/json](https://github.com/nlohmann/json) и [Google Test](https://github.com/google/googletest). При отсутствии локальной установки CMake загружает их через `FetchContent` (для первой сборки требуется доступ к интернету).

## Сборка и запуск

Из корневой папки репозитория:

```bash
cmake -S . -B build
cmake --build build
```

Запуск из корневой папки репозитория на Windows с MinGW:

```powershell
.\build\search_engine.exe
```

На Linux/macOS:

```bash
./build/search_engine
```

При использовании многоконфигурационного генератора CMake (например, Visual Studio) исполняемый файл может находиться в `build/Debug/`.

**Рабочая директория должна совпадать с корнем проекта:** программа ищет `config.json` и `requests.json` относительно неё. В CLion для конфигурации `search_engine` следует установить `Working directory: $ProjectFileDir$`.

## Формат данных и принцип поиска

- `config.json` содержит название движка, версию, ограничение `max_responses` (по умолчанию — 5) и массив путей `files`.
- `requests.json` содержит массив текстовых запросов `requests`.
- `answers.json` формируется автоматически: для каждого запроса записываются `result` и, при наличии совпадений, список `relevance` с полями `docid` и `rank`.

При поиске учитываются уникальные слова запроса. В выдачу попадают документы с одним или несколькими совпадениями — по логике примера `TestTop5` из задания. Релевантность рассчитывается как сумма частот слов запроса в документе, делённая на максимальную такую сумму среди найденных документов. При равных оценках документы сортируются по `docid`.

## Тестирование

```bash
ctest --test-dir build --output-on-failure
```

В CLion тесты можно запустить через цель `search_tests`.

Проект содержит **12 тестов**, охватывающих индексацию, повторное построение индекса, расчёт релевантности, формат ответов и обработку ошибок JSON. Нагрузочная проверка включает **1000 документов по 1000 слов** и **1000 поисковых запросов**.

Результат локального запуска в CLion: **12 тестов из 12 пройдены**.
